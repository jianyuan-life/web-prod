# C／G15 市場與介面可驗收基準

日期：2026-08-09
範圍：C 人生藍圖、G15 家族藍圖的產品頁、資料填寫、結帳、線上報告閱讀與 PDF 銜接
不在本次範圍：E3 月度精選、命理計算規則正確性、正式環境部署

## 先說結論

目前 C／G15 並不是「什麼都沒有」。程式中已經具備一套相當完整的諮詢產品骨架：產品頁先說使用情境與交付內容，結帳前交代一次性付款與服務邊界，G15 會限制成員資格並要求同意，新的報告閱讀器也已拆成「30 秒先讀、3 分鐘導讀、完整報告、依據與限制」四層。

真正的差距不是再加更多金色、陰影或動畫，而是把整段體驗閉合：

1. 購買前看不到一份真正可試讀的虛構樣本，使用者仍要靠文字想像成品。
2. 方案名稱與價格目前在多個檔案重複寫入；今天數字一致，不代表日後不會漂移。
3. G15 的同意目前主要由付款者一次勾選，尚未做到每位成年成員可獨立知情、同意或撤回。
4. 新閱讀器的層次清楚，但尚未看見跨裝置續讀、書籤、目前章節提示，以及網頁與 PDF 同一版本的可重跑比對。
5. 程式已有焦點樣式、窄版斷點與減少動態效果，但這份盤點沒有拿到真實裝置、螢幕閱讀器、實際付款沙盒與正式流量數據，因此不能把「程式中有寫」當成使用者已經順利完成。

市場上做得好的產品也不是共同採用某一種美術風格。它們共同做到的是：先讓人理解自己會得到什麼，公開樣本或互動預覽，清楚交代資料限制與付款條件，再把長篇洞察拆成可以先看重點、回頭深讀、實際練習的路徑。

## 判讀方式

本文把資訊分成兩類：

- **已觀察**：2026-08-09 直接查看官方產品頁、官方說明頁、官方樣本，或目前工作樹中的程式碼所得。
- **推論**：根據已觀察到的做法，推導出適合鑑源的設計方向。推論不是競品已證明可提高轉換率，也不是命理內容正確性的證明。

目前狀態只用四種文字，不用主觀分數：

- **已有**：目前程式可直接看到主要能力。
- **部分**：已有骨架，但缺少一段流程、例外狀態或實際使用證據。
- **未見**：在本文列出的搜尋範圍內沒有找到。
- **不適用**：該條只屬於另一個方案。

只有在每一項達成條件都有實際畫面、操作結果或可重跑測試支撐時，才適合稱為完成。視覺喜好票選只能補充，不能取代這些條件。

### 跨產業的結帳與可用性基準

- [Stripe Checkout 官方文件](https://docs.stripe.com/payments/checkout) 顯示完整付款頁可提供訂單摘要、折扣、促銷碼、本地付款方式與付款後流程。對鑑源而言，Stripe 頁面不是卸責點；送出前的鑑源頁仍需完整顯示方案、成員、折抵、實付與一次性付款。
- [W3C 表單指引](https://www.w3.org/WAI/tutorials/forms/) 要求標籤、欄位群組、填寫說明與錯誤回饋可被輔助工具理解；[WCAG 2.2](https://www.w3.org/TR/WCAG22/) 提供對比、鍵盤焦點、重排與操作目標的判準。
- [Web Vitals](https://web.dev/articles/vitals) 目前的良好門檻為第 75 百分位 LCP 不高於 2.5 秒、INP 不高於 200 毫秒、CLS 不高於 0.1；桌機與行動裝置應分開看。

## 建議的實作次序

### 先完成，否則不宜宣稱商業化完成

1. 把 C／G15 名稱、價格、幣別、一次性條款與包含內容收斂到單一來源，讓產品頁、須知、結帳、最後核對與 Stripe 自動比對。
2. 各做一份公開的虛構樣本：C 一人、G15 三位成年人；同時提供網頁試讀與 PDF，清楚標示虛構資料。
3. 為 G15 補上逐人同意設計，至少要能知道誰同意了什麼、何時同意、如何撤回，以及共同報告會分享哪些資訊。
4. 以 Stripe 測試模式完整走過原價、優惠、積分、零元、付款失敗、付款返回與重複點擊；每次都核對方案與實付。
5. 產出同一份 C／G15 的網頁與 PDF，逐章、逐頁比對資料基準日、結論、限制與版面。

### 接著完成，讓豐富內容真的讀得完

1. 報告加入目前章節、上次閱讀位置與段落收藏；保留 30 秒、3 分鐘、完整內容、依據四層，不再增加第五套平行導覽。
2. 每個主要結論固定接一個生活情境、一個小做法、一個核對問題與一個停止條件。
3. G15 先呈現個人視角，再呈現兩兩互動，最後才是全家循環；任何共同建議都要寫明由誰、在什麼情境、多久後回看。
4. 長表單加入草稿恢復；只保存完成交易所需資料，並在保存前說明期限與刪除方式。

### 最後才做視覺加法

1. 保留暖紙張、墨色、朱紅／靛青／鼠尾草的編輯式方向；不要再把整頁改回單一深藍背景配大白卡。
2. 動畫只用於章節進場、步驟完成與對話框開合，時間短、可停用、不能延遲操作。
3. 所有新增色彩先算實際對比，再看美感；所有新增固定區塊先測 320px 重排與焦點遮擋。
